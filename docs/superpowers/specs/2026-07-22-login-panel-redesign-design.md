# 登录页右侧面板改版设计

## 1. 背景与目标

当前桌面端认证页面使用左右分栏卡片：左侧为品牌信息，右侧顶部为“登录 / 注册”页面导航，登录表单内部通过文字链接切换密码与短信验证码登录。

本次仅改造登录页右侧面板，使其接近用户提供的参考截图：

- 登录表单顶部改为“手机登录 / 密码登录”模式标签。
- 默认展示手机验证码登录。
- 输入框改为白底描边、较小圆角的轻量样式。
- 协议确认位于输入区与主按钮之间。
- 主按钮保留项目主题色，并将文案调整为“立即登录”。
- “忘记密码”和“注册”入口移至主按钮下方。

左侧品牌区、注册页、认证接口和后台配置模型不在本次改造范围内。

## 2. 实现边界

采用局部改造方案：登录页不再使用 `AuthLayout` 提供的“登录 / 注册”顶部导航，而由 `UserAuthForm` 渲染登录模式标签与底部辅助入口。注册页继续使用现有布局和导航，不改变其表单、路由或业务流程。

不新建登录接口，不修改 Session、2FA、Passkey、OAuth、微信登录、人机验证或短信服务逻辑，也不增加新的后台配置项。

## 3. 页面结构

登录页右侧从上到下排列为：

1. “手机登录 / 密码登录”模式标签。
2. 当前模式的两个输入字段。
3. 后台启用协议时显示的协议勾选行。
4. 后台启用时显示的人机验证组件。
5. 主题色“立即登录”主按钮。
6. 辅助入口行：密码模式显示“忘记密码”；后台允许注册时显示“注册”。
7. 后台启用任一快捷登录渠道时，继续显示 Passkey、微信和 OAuth 快捷登录区。

右侧表单保持现有最大宽度与响应式容器，不改变整个认证卡片的桌面端左右比例。移动端继续隐藏左侧大面积品牌区并显示紧凑品牌头部。

## 4. 登录模式

### 4.1 手机登录

手机登录是进入页面后的默认模式。

- 第一个输入框为中国大陆手机号，保留现有 11 位数字限制和校验规则。
- 第二个输入框为 6 位短信验证码。
- 验证码按钮位于第二个输入框右侧，继续使用现有发送状态、倒计时、手机号校验和人机验证就绪状态。
- 提交继续调用 `POST /api/user/login`，用户名字段传手机号，密码字段传短信验证码。

### 4.2 密码登录

- 第一个输入框继续接受用户名、邮箱或手机号，不能因参考截图文案而收窄现有账户标识能力。
- 第二个输入框为密码，并保留显示/隐藏密码按钮、`current-password` 自动填充语义和键盘操作。
- “忘记密码”仅在密码模式下显示并跳转 `/forgot-password`。
- 提交继续调用 `POST /api/user/login`，并保持 2FA、登录成功重定向和错误提示逻辑。

### 4.3 模式切换

- 标签使用原生按钮或语义等价的可键盘操作控件。
- 当前标签以深色正文和底部强调线表示，非当前标签使用次要文字颜色。
- 切换模式时沿用当前行为，清空用户名与密码/验证码字段，避免不同登录凭据串用。
- 切换不改变 URL，不新增路由或查询参数。

## 5. 后台动态配置

登录页继续以 `/api/status` 为唯一配置来源，不将认证能力固定写死。

| 配置或能力 | 页面行为 |
|---|---|
| `password_login_enabled` | 继续遵循现有后端总登录开关。关闭时不把手机或密码登录伪装成可用，显示现有不可用提示，同时保留已启用的替代登录渠道。 |
| `register_enabled` | 为 `false` 时隐藏登录页底部“注册”入口。 |
| `password_register_enabled` | 为 `false` 时隐藏登录页底部“注册”入口。 |
| `self_use_mode_enabled` | 为 `true` 时隐藏登录页底部“注册”入口。 |
| `user_agreement_enabled` | 启用时显示用户协议链接并要求勾选。 |
| `privacy_policy_enabled` | 启用时显示隐私政策链接并要求勾选。 |
| 人机验证配置 | 继续由 `useHumanVerification` 选择关闭、Turnstile 或阿里云验证码。 |
| `passkey_login` | 启用且浏览器支持时显示 Passkey 入口。 |
| `wechat_login` | 启用时显示微信登录入口和现有弹窗。 |
| OAuth 渠道配置 | 仅显示后台实际启用的 GitHub、Discord、OIDC、LinuxDO 和自定义 OAuth 渠道。 |

本次不增加单独的短信登录开关。当前后端的 `password_login_enabled` 会在 `/api/user/login` 入口统一拦截登录，因此前端不能假设关闭密码登录后短信登录仍然可用。

## 6. 视觉规范

- 模式标签靠左排列，间距接近参考截图，不保留登录页原有整行“登录 / 注册”分隔线。
- 输入框高度约 46 至 48 像素，使用白色或主题背景、1 像素中性描边和约 12 像素圆角。
- 登录输入框移除左侧用户、手机、锁和盾牌图标，减少视觉噪声；密码显示按钮继续使用项目现有图标库。
- 获取验证码、忘记密码和注册沿用项目主题链接色，并提供悬停与键盘焦点状态。
- 主按钮高度约 48 像素，沿用现有 `sf-btn-primary` 主题样式、白色文字和约 12 像素圆角；颜色随项目主题与深色模式变化，不固定写死为黑色。
- 错误文本保留在对应字段下方。错误出现时允许表单纵向增高，不使用固定高度裁切内容。
- 快捷登录区延续现有动态布局，但与主按钮和辅助入口之间保持明确间距。

## 7. 数据流与错误处理

表单继续使用 React Hook Form 与 Zod。模式变化决定当前校验 schema：手机模式校验大陆手机号和短信验证码，密码模式使用现有登录 schema。

提交顺序保持为：

1. 检查协议确认。
2. 完成人机验证。
3. 设置加载状态并提交登录请求。
4. 服务端要求 2FA 时跳转 `/otp`。
5. 否则刷新当前用户并跳转 `redirect` 或默认页面。
6. 在成功、业务失败和传输异常后正确恢复加载状态。

发送短信失败、倒计时、重复提交防护和全局 API 拦截器行为保持不变。

## 8. 可访问性与响应式

- 模式标签具有明确的当前状态，可由键盘聚焦与切换。
- 输入框保留 `aria-label`、`autocomplete`、`inputmode` 和最大长度语义。
- 密码可见性按钮继续提供动态可访问名称。
- 协议勾选框与文字标签保持关联。
- 装饰性图标不新增；功能图标提供文本等价。
- 至少验收 390 像素移动端和 1280 像素桌面端，不允许横向滚动、入口遮挡或错误信息裁切。
- 深色模式下检查输入框、按钮、链接、错误文字和焦点环对比度。

## 9. 预计修改范围

- `web/default/src/features/auth/sign-in/index.tsx`：登录页不再请求共享布局渲染顶部“登录 / 注册”导航。
- `web/default/src/features/auth/sign-in/components/user-auth-form.tsx`：调整模式标签、字段布局、主按钮、协议位置和辅助入口，并保留所有动态认证渠道。
- `web/default/src/features/auth/components/auth-form-styles.ts`：如登录与注册无法共用新输入样式，则增加登录页专用样式常量，不覆盖注册页现有视觉。
- `web/default/src/features/auth/components/auth-password-input.tsx`：仅在需要支持登录页专用样式时增加可选外观参数，默认行为保持兼容。
- `web/default/src/i18n/locales/*.json`：只在新增用户可见文案键时同步多语言；优先复用现有翻译键。
- 登录模式与配置可见性相关测试文件：验证默认手机模式、模式切换、注册入口开关和协议开关等用户行为。

## 10. 验收标准

- 登录页顶部显示“手机登录 / 密码登录”，默认激活手机登录。
- 手机模式可发送验证码、显示倒计时并提交登录。
- 密码模式可显示/隐藏密码、进入忘记密码并提交登录。
- 注册入口仅在现有三个注册条件共同允许时出现，并跳转现有 `/sign-up` 页面。
- 协议、人机验证、Passkey、微信和 OAuth 均严格按后台状态显示。
- 登录页符合目标截图的白底描边输入框、主题色主按钮和底部辅助入口结构。
- 注册页视觉和交互不因本次登录页改造发生变化。
- TypeScript 类型检查、前端 lint 和生产构建通过。
- 浏览器中完成手机/密码切换、协议启停、注册启停、快捷登录启停、桌面端、移动端和深色模式视觉检查。

## 11. 非目标

- 不修改注册页或注册业务字段。
- 不新增手机号找回密码。
- 不改变大陆手机号校验范围。
- 不新增短信登录后台开关。
- 不修改后端接口、数据库、Session 或认证安全策略。
- 不移除或替换现有项目品牌、版权和归属信息。
