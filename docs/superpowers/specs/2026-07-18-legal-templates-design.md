# 用户协议与隐私政策模板设计

## 1. 目标

为中国大陆企业面向境内用户运营的 AI API 聚合与计费平台起草两份简体中文 Markdown 模板：

- 《用户协议》
- 《隐私政策》

模板应可直接粘贴到 new-api 后台的 `legal.user_agreement` 与 `legal.privacy_policy` 配置项中，并由现有公开页面展示。

## 2. 适用场景

- 运营主体：中国大陆企业，具体主体信息由部署方填写。
- 服务对象：中华人民共和国境内用户，包括个人用户和企业/组织用户。
- 服务形态：统一接入多个第三方人工智能模型，通过 API、控制台或其他产品界面提供模型路由、调用、用量统计、配额、充值及相关管理能力。
- 文本定位：面向正式上线前法务复核的通用运营模板，不替代针对实际业务、资质和数据流的专项法律意见。

## 3. 参考边界

模板吸收 new-api 官方公开材料中的以下合规边界，但不复制其文本：

- 上游 API Key、模型服务、支付服务及其他第三方能力应当合法取得授权。
- 用户和部署方均应遵守上游服务条款、平台规则及所在地法律法规。
- 面向公众提供生成式人工智能服务时，运营方应自行履行适用的备案、许可、内容安全、身份管理、日志留存、消费者保护、税务和支付义务。
- 充值、兑换、邀请奖励及计费能力仅可用于合法授权的服务场景。

模板同时考虑《中华人民共和国个人信息保护法》《网络数据安全管理条例》《生成式人工智能服务管理暂行办法》《互联网信息服务深度合成管理规定》《人工智能生成合成内容标识办法》等现行规则。

## 4. 方案选择

采用“平衡合规版”：覆盖平台真实存在的主要风险和数据处理活动，同时使用可删减条款与占位符，避免承诺尚未确认的资质、备案、实名能力、具体保存期限或第三方服务。

不采用以下方案：

- 精简上线版：文本较短，但对 AI 输出、上游服务、计费、内容治理和个人信息处理覆盖不足。
- 严格公众服务版：容易写入系统尚未具备或尚未核实的实名、备案、安全评估和内容审核承诺。

## 5. 《用户协议》结构

1. 导言、接受方式与运营主体
2. 定义与服务说明
3. 账号注册、身份信息与账号安全
4. API Key、访问令牌及凭证管理
5. 服务开通、配额、计费、充值、退款与发票
6. 第三方模型和上游服务
7. 用户使用规范与禁止行为
8. 用户输入、生成内容和知识产权
9. 人工智能输出的局限与风险提示
10. 生成合成内容标识和用户发布义务
11. 内容治理、风控、暂停与终止服务
12. 服务变更、可用性和免责声明
13. 违约责任、赔偿与责任限制
14. 未成年人保护
15. 协议更新、通知、适用法律、争议解决与联系方式

其中，生成合成内容标识条款应明确：平台可能根据适用规则在界面、输出内容或文件元数据中添加显式或隐式标识；用户不得恶意删除、篡改、伪造或隐匿标识；用户对外发布生成合成内容时应依法主动声明和标识。

## 6. 《隐私政策》结构

1. 引言、适用范围与个人信息处理者
2. 收集和使用个人信息的原则
3. 个人信息处理清单，至少覆盖：
   - 注册与账号资料：用户名、显示名称、密码散列、手机号、邮箱
   - 第三方登录和安全凭证：OAuth 标识、Passkey/二次验证相关信息
   - 设备与日志：IP、浏览器/设备信息、登录时间、操作日志、异常日志
   - API 与服务使用：访问令牌标识、模型名称、调用时间、请求状态、Token 用量、配额与计费数据
   - 用户提交内容：提示词、文本、图片、音频、视频、文件或其他请求内容，以及模型输出；仅在实际传输、缓存、审计或故障排查需要时处理
   - 交易信息：订单号、金额、支付渠道、交易状态；原则上不直接保存完整银行卡号或第三方支付密码
   - 客服、投诉和安全事件材料
4. Cookie、本地存储及同类技术
5. 委托处理、共享、转让和公开披露
6. 向上游模型服务商传输数据的特别说明
7. 跨境提供个人信息的条件性说明
8. 保存地点、期限、删除和匿名化
9. 安全措施与安全事件响应
10. 用户查阅、更正、复制、删除、撤回同意、注销及投诉权利
11. 未成年人个人信息保护
12. 政策更新与联系方式

隐私政策不得笼统宣称“不会收集任何个人信息”或“绝不会共享数据”。应说明：为完成模型调用，用户提交内容可能被传输给用户选择或系统路由到的第三方模型服务商；具体厂商、处理地点和留存规则受实际启用渠道及其政策影响。

## 7. 占位符

两份模板统一使用以下占位符；部署前必须替换或删除：

- `[平台名称]`
- `[运营主体全称]`
- `[统一社会信用代码]`
- `[注册地址]`
- `[常用办公地址]`
- `[联系邮箱]`
- `[客服电话]`
- `[投诉举报渠道]`
- `[生效日期]`
- `[更新日期]`
- `[账号信息保存期限]`
- `[调用日志保存期限]`
- `[交易记录保存期限]`
- `[争议管辖法院所在地]`
- `[实际启用的支付渠道]`
- `[实际启用的第三方登录渠道]`
- `[主要上游模型服务商或查询入口]`
- `[境外接收方清单或查询入口]`

如尚未启用某项能力，应删除对应条款中的具体示例，不得仅保留未替换的占位符对外发布。

## 8. 写作与交付格式

- 使用简体中文和 Markdown 标题、列表、表格。
- 保持正式、清晰、可理解，避免不必要的法律术语堆叠。
- 重要风险使用加粗提示，但不使用恐吓性或显失公平表述。
- 两份正文分别作为独立 Markdown 内容交付，可直接复制到后台。
- 正文顶部包含版本、生效日期、更新日期和运营主体占位信息。
- 正文末尾附“上线前必填项”注释块，提醒运营方替换占位符；该注释块在正式发布前可删除。

## 9. 非目标

- 不确认或代办 ICP 备案、算法备案、安全评估、生成式人工智能服务备案或行政许可。
- 不虚构平台已经取得任何资质或完成任何备案。
- 不承诺系统当前没有实现的实名验证、内容审核、数据本地化、自动删除或用户自助导出能力。
- 不替代律师根据实际运营主体、部署区域、上游厂商、支付模式和数据流进行最终审查。

## 10. 验收标准

- 两份模板均可独立阅读和直接粘贴到后台。
- 用户协议覆盖 AI API 平台的账号、凭证、计费、上游授权、内容与标识风险。
- 隐私政策准确披露账号、日志、调用内容、支付和第三方传输等主要数据处理活动。
- 所有未确认事实均通过显式占位符或条件性表述处理。
- 不出现 `TBD`、`TODO`、空白章节、虚假资质或无条件合规承诺。
- 上线前必填信息和建议删除的可选条款清晰可识别。
